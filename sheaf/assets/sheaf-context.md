## Quick Start Example

;; Simple MLP forward pass with parameter destructuring
(defn forward [x p]

    {:p new-p :m new-m :v new-v :t (+ t 1) :loss loss}))

## Core Concepts

### 1. Everything is Differentiable

- All operations compile to JAX primitives
- Full gradient support via `(value-and-grad func)`
- Works with JAX transformations: `jax.jit`, `jax.vmap`, `jax.grad`

### 2. Dictionary-Based Parameters

Neural network parameters are stored in nested HashableDicts:

```sheaf
{:l1 {:W weights :b biases}
 :l2 {:W weights :b biases}}
```

### 3. Python Integration

```python
from sheaf import Sheaf

shf = Sheaf()
shf.load("(defn add-five [x] (+ x 5))")
result = shf.add_five(10)  # Direct Python call

# Access compiled JAX function
jax_func = shf.registry["add-five"]
```

### 4. Macro System

Sheaf supports compile-time macros with quasiquote syntax:

```sheaf
(defmacro when [cond body]
  `(if ~cond ~body nil))

;; Usage:
(when (> x 0)
  (print "positive"))

;; Expands to:
(if (> x 0)
  (print "positive")
  nil)
```

**Quote and quasiquote operators:**

- `'expr` or `(quote expr)` - quote: prevent evaluation, return data as-is
- `` `expr `` - quasiquote: create template with selective evaluation
- `~expr` - unquote: evaluate expression inside quasiquote
- `~@expr` - unquote-splicing: splice list into quasiquote

**Critical Distinction: Quote Before Square Brackets**

The quote prefix changes semantics fundamentally:

- `[1 2 3]` (unquoted) → JAX Tensor (evaluated immediately to numeric array)
- `'[1 2 3]` (quoted) → Sheaf list (unevaluated data, treated as static structure)

Always quote shapes for functions that expect static data:

- ✓ Correct: `(ones '[10 20])`, `(reshape x '[2 -1])`
- ✗ Wrong: `(ones [10 20])`, `(reshape x [2 -1])` (these create tensors first!)

**Quote examples:**

```sheaf
'foo              ; => foo (symbol, not evaluated)
'(+ 1 2)          ; => (+ 1 2) (list, not evaluated)
`(+ 1 ~(* 2 3))   ; => (+ 1 6) (quasiquote with unquote)
```

**Standard macros** (from `lib/macros.shf`):

- `when` - conditional execution (returns nil if false)
- `unless` - inverse conditional
- `comment` - comment out code blocks

- Network topology and layer composition
- Forward and backward pass structure
- Gradient flow and differentiation
- Functional parameter updates
- Trainable state management

#### Advanced Macros: `defmodel`

Sheaf macros can manipulate code at compile-time using Lisp functions. The `defmodel` macro (from `lib/defmodel.shf`) demonstrates this:

```sheaf
(use defmodel)

(defmodel my-mlp [x]
  (layer :l1 (linear 128) relu)
  (layer :l2 (linear 10) softmax))
```

**Expands to:**

```sheaf
(defn my-mlp [x p]
  (as-> x _
    (with-params [p :l1] (relu (+ (@ _ W) b)))
    (with-params [p :l2] (softmax (+ (@ _ W) b)))))
```

**How it works:**

- The macro uses `map` and `transform-layer` to process each layer specification
- Functions like `map`, `first`, `nth` operate on **S-expressions as data** at compile-time
- The `~@` (unquote-splicing) operator injects the transformed layers into the template

**Key insight:** Macros distinguish between:

- **Symbols as data** (e.g., `'x'` remains a symbol in the AST)
- **Functions as code** (e.g., `(first params)` executes `first` at macro expansion time)
- **First-class functions** (e.g., `transform-layer` in `(map transform-layer layers)`)

This allows powerful metaprogramming while maintaining code clarity.

## Syntax at a Glance

### Literals

```sheaf
[1 2 3]          ; Vector literal (JAX array when numeric, tuple otherwise)
[D D]            ; Shape literal (evaluates to tuple when symbols present)
[[1 2] [3 4]]    ; Nested vectors (2D JAX array)
{:a 1 :b 2}      ; Dictionary (like Clojure/Python)
{"key" value}    ; Dictionary with string keys
:keyword         ; Keyword (evaluates to string "keyword")
true / false     ; Booleans (lowercase)
nil              ; None
...              ; Ellipsis (for indexing/einsum)
```

**Bracket contexts:**

- `[]` in **binding context** (first arg to defn, let, fn): destructuring pattern
- `[]` in **expression context** (function arguments, return values): data literal

### Core Operators

**Function Definition**

```sheaf
(defn name [args] body)              ; Standard function
(defn :jit name [args] body)         ; JIT-compiled (faster, limited control flow)
(fn [args] body)                     ; Anonymous function (preferred)
```

**Binding & Scope**

```sheaf
(let [x val y val2] body)            ; Sequential local bindings
(with-params params body)            ; Auto-destructure dict (:W, :b, etc.)
```

**Control Flow**

```sheaf
(if cond then else)                  ; Branching (avoid in JIT functions)
(case expr clause1 clause2 ...)      ; Pattern matching (each clause: (pattern result))
(where cond true-val false-val)      ; Differentiable select (use in JIT)
(repeat [i n] [acc init] body)       ; Loop with accumulator
(scan fn init xs)                    ; Fold with intermediate results (like Haskell scanl)
(static expr)                        ; Force static evaluation in JIT
```

**Macros**

```sheaf
(defmacro name [params] template)    ; Define compile-time macro
'expr / (quote expr)                 ; Quote: prevent evaluation
`expr                                ; Quasiquote: create template
~expr                                ; Unquote: evaluate in template
~@expr                               ; Unquote-splicing: splice list in template

;; Example:
(defmacro when [cond body]
  `(if ~cond ~body nil))
```

**Functional Operations**

```sheaf
(map func coll)                      ; Apply function to each element
(reduce func acc coll)               ; Reduce collection with accumulator
(apply func args-list)               ; Apply function to list of arguments
(vmap func)                          ; Vectorized map (JAX vmap) - auto-batch over axis 0
(vmap func axis)                     ; Vectorized map over specified axis
(vmap func [0 nil])                  ; vmap first arg on axis 0, keep second fixed
```

**Threading Macros**

```sheaf
(-> x (f1) (f2 a))                   ; Thread-first: (f2 (f1 x) a)
(as-> init name step1 step2)         ; Thread-as: bind value with custom name at each step
(->> x (map f) (filter pred))        ; Thread-last: (filter pred (map f x))
```

**Threading Macros in Detail:**

Threading macros help avoid deeply nested function calls. Choose based on your data flow:

- **`->`** (thread-first): Inserts value as **first argument**

  ```sheaf
  (-> x (relu) (reshape '(10 -1)) (transpose '[1 0]))
  ; Equivalent to:
  (transpose (reshape (relu x) '(10 -1)) '[1 0])
  ```

- **`->>`** (thread-last): Inserts value as **last argument**

  ```sheaf
  (->> (range 10) (map (fn [x] (* x 2))) (reduce + 0))
  ; Equivalent to:
  (reduce + 0 (map (fn [x] (* x 2)) (range 10)))
  ```

- **`as->`** (thread-as): Binds value to **custom variable** at each step
  ```sheaf
  (as-> (forward x params) output
    (reshape output '[batch 10])
    (softmax output :axis -1)
    (mean output :axis 0))
  ; Equivalent to:
  (let [output (forward x params)
        output (reshape output '[batch 10])
        output (softmax output :axis -1)
        output (mean output :axis 0)]
    output)
  ```

## Common Patterns

### Pattern 1: Multi-Layer Perceptron

```sheaf
(defn forward [x p]
  (as-> x h
    (with-params [p :l1]
      (relu (+ (@ h W) b)))
    (with-params [get p :l2]
      (sigmoid (+ (@ h W) b)))))
```

### Pattern 2: Transformer Block (from BareGPT)

```sheaf
(defn transformer-block [x layer-p config]
  (as-> x h
    ;; 1. Self-Attention
    (-> h
        (layer-norm (get layer-p :ln1) 2)
        (multi-head-attention layer-p config)
        (first) ;; Get the attention output, ignore weights
        (+ h))  ;; Residual 1
    ;; 2. MLP
    (-> h
        (layer-norm (get layer-p :ln2) 2)
        (mlp (get layer-p :mlp))
        (+ h)))) ;; Residual 2
```

```sheaf
(defn train-step [params m v t inputs targets config]

        loss-fn (fn [p] (cross-entropy-loss (model inputs p config) targets))
        [loss grads] ((value-and-grad loss-fn) params)
        [new-params new-m new-v new-t] (adam-step params grads m v t lr 0.9 0.999 1e-8)]
    {:loss loss :params new-params :m new-m :v new-v :t new-t}))
```

### Pattern 4: Einsum for Multi-Head Attention

```sheaf
;; Q, K, V projections [Batch, Heads, Time, Head_dim]
(let [Qh (einsum "... t d, d h k -> ... h t k" X Wq_multi)
      Kh (einsum "... t d, d h k -> ... h t k" X Kh_multi)
      Vh (einsum "... t d, d h k -> ... h t k" X Vh_multi)]

```

### Pattern 5: Batching with vmap

```sheaf
;; Define single-sample forward pass
(defn forward-single [x params]
  (with-params [params]
    (sigmoid (+ (@ x W) b))))

;; Batch it automatically with vmap
(let [batch-forward (vmap forward-single [0 nil])  ; vmap over axis 0 of inputs, keep params fixed
      batch-results (batch-forward X params)]
  batch-results)

;; Or use the defbatch macro (from lib/macros.shf) for cleaner syntax:
(defbatch linear-layer [x w b] [0 nil nil]
  (+ (@ x w) b))
; Now (linear-layer batch-x W b) automatically batches over first axis of x
```

## Practical Training Guide

This section provides complete, production-ready patterns for training neural networks in Sheaf. It addresses the most common challenges beginners face.

### Complete End-to-End Training Example

Here's a complete MLP training pipeline from initialization to evaluation:

```sheaf
(use nn)
(use optim)

;; Define the model
(defn forward [x params]
  (as-> x h
    (with-params [params :l1]
      (relu (+ (@ h W) b)))
    (with-params [params :l2]
      (sigmoid (+ (@ h W) b)))))

;; Training step with proper gradient computation
(defn train-step [params m v t x y lr]
  (let [loss-fn (fn [p] (mse-loss (forward x p) y))
        [loss grads] ((value-and-grad loss-fn) params)
        [new-p new-m new-v] (adam-step params grads m v t lr 0.9 0.999 1e-8)]
    {:params new-p :m new-m :v new-v :t (+ t 1) :loss loss}))

;; Evaluation (no gradient computation)
(defn evaluate [params x y]
  (let [predictions (forward x params)
        loss (mse-loss predictions y)]
    loss))
```

**Building blocks in pure Sheaf:**

Initialization with Xavier scaling:

```sheaf
(defn init-layer [key input-size output-size]
  (let [scale (sqrt (/ 2.0 (+ input-size output-size)))
        W (random-normal key '[input-size output-size])]
    {:W (* W scale)
     :b (zeros '[output-size])}))
```

Training step with gradient computation:

```sheaf
(defn train-step [params loss-fn x y lr]
  (let [[loss grads] ((value-and-grad loss-fn) params)]
    {:p (sgd-step params grads lr)
     :loss loss}))
```

Loop pattern for n training steps:

```sheaf
(defn train-epoch [params loss-fn xs ys lr n-steps]
  (reduce (fn [state _]
            (let [result (train-step (get state :p) loss-fn xs ys lr)]
              {:p (get result :p)
               :loss (get result :loss)}))
          {:p params :loss 0.0}
          (range n-steps)))
```

Multi-epoch training with progress reporting:

```sheaf
(defn train-model [params loss-fn xs ys lr n-epochs steps-per-epoch]
  (reduce (fn [state epoch]
            (let [epoch-result (train-epoch (get state :p) loss-fn xs ys lr steps-per-epoch)
                  loss-val (get epoch-result :loss)]
              ;; Report progress
              (print (str-call "format" "[epoch {}] loss: {:.6f}" epoch loss-val))
              {:p (get epoch-result :p)
               :loss loss-val
               :epoch epoch}))
          {:p params :loss 0.0 :epoch 0}
          (range n-epochs))))
```

**Using these building blocks:**

```sheaf
;; 1. Define your loss function (model-specific)
(defn my-loss [params x y]
  (mse-loss (my-model x params) y))

;; 2. Initialize your parameters
(let [params (init-layer key 10 8)]

  ;; 3. Train
  (train-model params my-loss X Y 0.01 100 50))
```

### Weight Initialization Strategies

**Why it matters:** Poor initialization causes slow convergence or NaN losses.

| Strategy            | Best For                       | Scale    | Function                       | Notes                                                |
| ------------------- | ------------------------------ | -------- | ------------------------------ | ---------------------------------------------------- |
| **Xavier Normal**   | `tanh`, `sigmoid`              | ~0.1-0.5 | `init-xavier-normal`           | Uniform variance across layers                       |
| **Xavier Uniform**  | `tanh`, `sigmoid` (faster)     | ~0.1-0.5 | `init-xavier-uniform`          | More uniform distribution                            |
| **Kaiming Normal**  | `relu`, `elu`, `gelu`          | ~0.1-0.5 | `init-kaiming-normal`          | Account for ReLU dead zones                          |
| **Kaiming Uniform** | `relu`, `elu`, `gelu` (faster) | ~0.1-0.5 | `init-kaiming-uniform`         | Faster convergence                                   |
| **LeCun Normal**    | `selu` activation              | ~0.1     | `init-lecun-normal`            | For self-normalizing nets                            |
| **LeCun Uniform**   | `selu` activation (faster)     | ~0.1     | `init-lecun-uniform`           | Faster but less stable                               |
| **Orthogonal**      | RNNs, GRUs, LSTMs              | 1.0      | `init-orthogonal`              | **CRITICAL for RNNs** - prevents vanishing gradients |
| **Zero**            | Biases                         | 0.0      | `(zeros shape)`                | Always use for biases                                |
| **Small Normal**    | RNN biases, skip connections   | ~0.01    | `(* (random-normal ...) 0.01)` | Slight random offset for biases                      |

**Sheaf implementations:**

```sheaf
;; Xavier Normal (for tanh/sigmoid)
(defn init-xavier-normal [key shape]
  (let [fan-in (first shape)
        fan-out (nth shape 1)
        scale (sqrt (/ 2.0 (+ fan-in fan-out)))]
    (* (random-normal key shape) scale)))

;; Kaiming Normal (for ReLU)
(defn init-kaiming-normal [key shape]
  (let [fan-in (first shape)
        scale (sqrt (/ 2.0 fan-in))]
    (* (random-normal key shape) scale)))

;; LeCun Normal (for SELU)
(defn init-lecun-normal [key shape]
  (let [fan-in (first shape)
        scale (sqrt (/ 1.0 fan-in))]
    (* (random-normal key shape) scale)))

;; Orthogonal (for RNNs)
(defn init-orthogonal [key shape]
  ;; Simplified: random normal + QR decomposition
  ;; For production, use init-orthogonal from lib/nn.shf
  (let [scale 1.0]
    (* (random-normal key shape) scale)))
```

**Usage:**

```sheaf
(let [[k1 k2 k3] (random-split key 3)]
  {:W-sigmoid (init-xavier-normal k1 '[10 8])      ; For sigmoid layer
   :W-relu    (init-kaiming-normal k2 '[8 16])     ; For ReLU layer
   :W-rnn     (init-lecun-normal k3 '[32 32])})    ; For SELU/RNN
```

### Loss Functions: When to Use Which

| Loss Function                                                         | Use Case              | Advantages                  | Disadvantages            |
| --------------------------------------------------------------------- | --------------------- | --------------------------- | ------------------------ |
| **MSE** `(mse-loss pred target)`                                      | Regression            | Simple, differentiable      | Sensitive to outliers    |
| **MAE** `(mae-loss pred target)`                                      | Robust regression     | Less sensitive to outliers  | Non-differentiable at 0  |
| **Cross-Entropy** `(cross-entropy-loss logits targets)`               | Multi-class (one-hot) | Standard for classification | Requires one-hot targets |
| **Sparse Cross-Entropy** `(sparse-cross-entropy logits targets :i32)` | Multi-class (integer) | Standard, cleaner targets   | Requires integer labels  |

**Quick examples:**

```sheaf
;; Regression: predict continuous values
(let [pred [1.5 2.1 0.9]
      target [1.0 2.0 1.0]]
  (mse-loss pred target))        ; => 0.043

;; Binary classification: sigmoid output + cross-entropy
(let [logits [[2.0 -1.0] [-1.0 2.0]]
      targets [[1.0 0.0] [0.0 1.0]]]
  (cross-entropy-loss logits targets))  ; => 0.814

;; Multi-class: integer labels (simpler!)
(let [logits [[10.0 1.0 0.1] [1.0 10.0 0.1]]
      targets [0 1] :i32]
  (sparse-cross-entropy logits targets :i32))  ; => 0.000174
```

### Hyperparameter Recommendations

**Learning Rate (most critical):**

- Start with `0.01` for most problems
- If loss is NaN or exploding: decrease to `0.001`
- If convergence is very slow: try `0.1` (but monitor for instability)
- Use learning rate decay for longer training: `lr_t = lr_0 * (0.95 ^ epoch)`

**Adam Optimizer (default choice):**

```sheaf
;; Standard configuration
(adam-step params grads m v t lr 0.9 0.999 1e-8)
;;                             ↑    ↑     ↑
;;                         beta1  beta2   eps
;; - beta1=0.9: momentum (exponential moving average of gradients)
;; - beta2=0.999: RMSProp (exponential moving average of gradient squares)
;; - eps=1e-8: numerical stability
```

**Batch size:**

- Smaller batches (16, 32): noisier updates, better generalization
- Larger batches (128, 256): faster computation, may overfit

### Debugging Training: Common Problems and Solutions

#### Problem 1: Loss is NaN

**Symptoms:** Loss becomes `nan` after first few iterations

**Common causes:**

1. Learning rate too high
2. Numerical instability in loss computation
3. Weights initialized to very large values

**Solutions:**

```sheaf
;; 1. Reduce learning rate
(adam-step params grads m v t 0.001 ...)  ; Was 0.01

;; 2. Add gradient clipping
(let [clipped-grads (clip-by-global-norm grads 1.0)]
  (adam-step params clipped-grads m v t lr 0.9 0.999 1e-8))

;; 3. Use more conservative initialization
(let [scale 0.01]  ; Smaller than default
  (tree-map (fn [x] (* x scale)) (random-normal key shape)))
```

#### Problem 2: Loss is Constant (Not Decreasing)

**Symptoms:** Loss stays the same across all epochs

**Common causes:**

1. Gradients are zero (model not connected to loss)
2. Learning rate too small
3. Model has no trainable parameters in critical layers

**Solutions:**

```sheaf
;; Debug 1: Check that gradients are non-zero
(let [loss-fn (fn [p] (mse-loss (forward x p) y))
      [loss grads] ((value-and-grad loss-fn) params)
      _ (guard :no-nan grads)]        ; Verify gradients are valid
  ...)

;; Debug 2: Verify forward pass works
(let [output (forward x params)]
  (guard :shape [32 10] output))      ; Check expected shape

;; Debug 3: Increase learning rate
(adam-step params grads m v t 0.1 ...)  ; Try 10x larger
```

#### Problem 3: Slow Convergence

**Symptoms:** Loss decreases very slowly, training takes forever

**Common causes:**

1. Learning rate too small
2. Bad weight initialization (all near 0 or near ±large)
3. Insufficient model capacity (too few neurons)

**Solutions:**

```sheaf
;; 1. Increase learning rate gradually
(let [lr (if (< t 100) 0.1 0.01)]  ; High LR early, then lower
  (adam-step params grads m v t lr 0.9 0.999 1e-8))

;; 2. Use better initialization
;; Xavier for tanh/sigmoid, Kaiming for relu

;; 3. Add more hidden units
;; Try doubling the hidden layer size: 4 -> 8 -> 16
```

#### Problem 4: Vanishing/Exploding Gradients

**Symptoms:** Gradients become very small (< 1e-7) or very large (> 1e+3)

**Solutions:**

```sheaf
;; Monitor gradient norms
(let [grads (grad-fn params)
      norms (tree-map (fn [g] (sqrt (sum (** g 2)))) grads)
      global-norm (global-norm grads)
      _ (guard :range [1e-6 100.0] global-norm)]  ; Flag if too small or large
  ...)

;; Clip gradients for stability
(let [clipped (clip-by-global-norm grads 1.0)]
  (adam-step params clipped m v t lr 0.9 0.999 1e-8))

;; Use better activation functions
;; - For deep networks: relu + batch norm
;; - For RNNs: use SELU or gated units
;; - Avoid sigmoid/tanh in very deep networks
```

## Gotchas & Common Mistakes

### ⚠️ Scalars vs Arrays

Sheaf uses JAX arrays as the fundamental data type. Python scalars (int, float) are automatically converted to JAX arrays when needed:

```sheaf
; Scalars are auto-converted
(+ 5 x)              ; 5 becomes a JAX scalar array
(* 3.14 tensor)      ; 3.14 becomes a JAX scalar array

; Vectors/arrays are JAX arrays from the start
[1 2 3]              ; JAX array of shape [3]

; To create a scalar tensor explicitly (rarely needed):
(reshape 42 )        ; Scalar tensor (shape [])
(+ 0 scalar-value)   ; Force conversion to array
```

**When you need explicit conversion:**

- Most operations auto-convert Python scalars
- If a function requires a tensor but you have a scalar, wrap it: `(reshape value)` or add 0: `(+ 0 value)`

## Common Implementation Mistakes

These are real errors that come up when implementing models:

### ❌ Missing Parentheses Around `defn`

**Wrong:**

```sheaf
defn forward [x p]
  (with-params [p] (+ (@ x W) b))
```

**Right:**

```sheaf
(defn forward [x p]
  (with-params [p] (+ (@ x W) b)))
```

**Explanation:** Sheaf is a Lisp. **Every form must be parenthesized**, including function definitions. Without the outer parentheses, `defn` is treated as a symbol, not a special form.

---

### ❌ Confusing `as->` and `let`

These are fundamentally different:

**`let` creates independent local variables. Use when binding multiple different values:**

```sheaf
(let [x-input (forward inputs params)
      y-target (get batch :labels)
      lr 0.001
      loss-fn (fn [p] (mse-loss (forward inputs p) y-target))]
  ;; All bindings are independent; they don't depend on each other
  (loss-fn params))
```

**`as->` threads a **single** value through transformations. Use when each step depends on the previous:**

```sheaf
(as-> (forward inputs params) x
  (relu x)
  (reshape x '[batch -1])
  (softmax x :axis -1)
  (mean x :axis 0))
;; Each step uses the result of the previous step
```

**Wrong (shadowing variable with `let`):**

```sheaf
; This works but is confusing - x is reassigned in each binding
(let [x (forward inputs params)
      x (relu x)                  ; x is redefined here
      x (linear x W b)]           ; x is redefined again
  x)
```

**Side-by-side comparison:**

| Task                                 | Use    | Example                                    |
| ------------------------------------ | ------ | ------------------------------------------ |
| Multiple independent bindings        | `let`  | `(let [a 1 b 2 c 3] ...)`                  |
| Single value through transformations | `as->` | `(as-> x h (f1 h) (f2 h))`                 |
| Single value, first-arg threading    | `->`   | `(-> x (f1) (f2 arg))` = `(f2 (f1 x) arg)` |
| Single value, last-arg threading     | `->>`  | `(->> xs (map f) (reduce + 0))`            |

**Real-world example:**

```sheaf
; Training step using both:
(let [;; Independent values
      params (get state :params)
      lr 0.001
      epoch (get state :epoch)
      loss-fn (fn [p] (cross-entropy-loss (model x p) y))]

  ;; Single gradient-update path (use threading)
  (as-> ((value-and-grad loss-fn) params) result
    (let [[loss grads] result]
      (adam-step params grads m v epoch lr 0.9 0.999 1e-8))))
```

---

### ❌ Initializing Adam State Incorrectly

**Wrong:**

```sheaf
(let [m {:w 0.0 :b 0.0}
      v {:w 0.0 :b 0.0}]
  (adam-step params grads m v t lr))
```

**Right:**

```sheaf
(let [m (tree-map-zeros params)  ; Create m with same structure as params
      v (tree-map-zeros params)  ; Create v with same structure as params]
  (adam-step params grads m v t lr))
```

**Explanation:** Adam optimizer states must match the nested structure of your parameters. Use `tree-map-zeros` to create zero-initialized states with the correct shape and nesting.

---

### ❌ Passing Sheaf-Only Functions to Python

**Wrong:**

```python
shf = Sheaf()
shf.load("(defn forward [x p] ...)")
# This will fail:
py_func = shf.forward  # ❌ forward not in registry
```

**Right:**

```python
shf = Sheaf()
shf.load("(defn forward [x p] ...)")
# Access via registry:
py_func = shf.registry["forward"]  # ✓ Works
result = py_func(x, params)
```

**Explanation:** Functions defined in Sheaf code are compiled into `shf.registry`. Access them via `registry["function-name"]`, not as attributes. Use `:env` in the REPL to see all available functions.

---

### ❌ Using Unquoted Shapes

**Wrong:**

```sheaf
(reshape x [3 4])      ; ❌ [3 4] becomes a JAX array, not a shape tuple
```

**Right:**

```sheaf
(reshape x '[3 4])     ; ✓ '(3 4) is a static shape tuple
```

**Explanation:** Shape arguments must be quoted to prevent evaluation. The quote `'` tells Sheaf to treat `[3 4]` as data, not as code to be evaluated into a JAX array.

---

### ❌ Forgetting Parameter Structure in `with-params`

**Wrong:**

```sheaf
(with-params [params]
  (+ (@ x w) b))      ; ❌ If params is {:l1 {:w W :b b}}, w and b aren't in scope
```

**Right:**

```sheaf
(with-params [params :l1]  ; ✓ Destructure the :l1 sub-dict
  (+ (@ x w) b))
```

**Or:**

```sheaf
(with-params [(get params :l1)]  ; ✓ Explicitly get the layer
  (+ (@ x w) b))
```

**Explanation:** `with-params` only auto-binds keys from the dict level you pass. If your parameters are nested, either destructure with a key or extract the sub-dict first.

## Advanced Topics: Shapes, State Threading & Limitations

### Quoted Forms & Static Shapes: A Critical Limitation

Sheaf uses **quoted forms** (lists starting with `'`) for shapes because they must be compile-time constants. This is a fundamental design choice for JAX compatibility:

```sheaf
;; ❌ WRONG - Cannot evaluate variables inside quotes
(let [hidden_size 8]
  (zeros '[hidden_size]))  ; Error: 'hidden_size' is not a static value

;; ✅ CORRECT - Use static shape values
(zeros '[8])              ; Creates shape [8]

;; ✅ CORRECT - Pre-computed static value
(let [hidden_size 8]
  (zeros '[8]))           ; This works - the literal 8 is static
```

**Why this limitation exists:**

JAX requires shape information at compile time to generate efficient code. Quoted forms (`'[...]`) are parsed as literal data structures, not evaluated expressions. This allows JAX to inspect shapes before execution.

**Workarounds:**

1. **Use static values:** Replace dynamic shapes with their literal numeric values

   ```sheaf
   (zeros '[128])         ; Static: always works
   (zeros '[hidden_size]) ; Dynamic: always fails
   ```

2. **Extract shape from existing tensors:** Use `(shape t)` to get dynamic shape

   ```sheaf
   ;; Get hidden size from parameter tensor
   (let [hidden_size (shape (get params :W_hh) 0)  ; Dynamic: [8]
         h0 (zeros (shape (get params :W_hh)))]    ; Matches W_hh shape
     ...)
   ```

3. **For RNNs:** Initialize hidden state from parameter shapes, not variables
   ```sheaf
   ;; ✅ Initialize h0 by copying shape of W_hh
   (let [h0 (zeros (shape (get params :W_hh)))]  ; Shape comes from parameter
     ...)
   ```

**Key insight:** Variables inside quotes are never evaluated. If you need dynamic shapes, extract them from existing tensors using `(shape tensor)`.

### Understanding `scan`: State Threading & Temporal Loops

`scan` is how you write loops with memory (state) that flows through time. Every iteration receives the current state and one input element, then returns a new state and an output.

**Basic pattern - accumulator:**

```sheaf
;; Simple accumulator: state is a running sum
(scan (fn [state x]           ; state=running_sum, x=current_element
        [(+ state x)          ; Return new state (updated sum)
         (+ state x)])        ; Return output (the new sum value)
      0.0                     ; Initial state (start sum at 0)
      [1.0 2.0 3.0])         ; Input sequence
; => [6.0 [1.0 3.0 6.0]]     ; Final: state=6, outputs=[1,1+2,1+2+3]
```

**RNN pattern - state threading:**

The key insight: **state in an RNN is the hidden vector**, which carries information through time:

```sheaf
;; Each iteration: (h_prev, x_t) -> (h_next, output)
(fn [h_prev x_t]
  ;; Compute new hidden state using both previous state and new input
  (let [h_next (tanh (+ (@ W_hh h_prev)  ; Recurrence: W_hh @ h_prev
                        (@ W_xh x_t)     ; Input: W_xh @ x_t
                        b_h))]           ; Bias
    [h_next h_next]))  ; Return [new_state, output]
```

**Critical: Structure matters**

- **First return element** `[new-state ...]` becomes next iteration's state
- **Second element** `[... output]` is what `scan` accumulates
- They can be the same (output all hidden states) or different (output only last layer)

```sheaf
;; Pattern 1: Output all hidden states (common for RNNs)
[h_next h_next]  ; state and output are the same

;; Pattern 2: Output only predictions from hidden state
[h_next (@ W_out h_next)]  ; state is h, output is prediction

;; Pattern 3: Multiple state components
[{:h h_next :c c_next}  ; state: both h and c (like LSTM)
 h_next]                 ; output: only h
```

### with-params: Accessing Nested Parameters

`with-params` makes certain keys in your parameter dictionary available as variables. But it only works one level deep:

```sheaf
;; Parameter structure
{:layer1 {:W [[1 2] [3 4]]
          :b [5 6]}
 :layer2 {:W [[7 8]]
          :b [9]}}

;; ✅ Access layer1 parameters
(with-params [params :layer1]
  (+ W b))  ; W and b from :layer1 are bound

;; ❌ FAILS - Can't skip levels
(with-params [params]
  (+ W b))  ; Error: W and b don't exist at root level

;; ✅ Two-step access
(with-params [params :layer1]
  (let [hidden (+ (@ x W) b)]
    (with-params [params :layer2]  ; Switch context
      (+ (@ hidden W) b))))
```

**For complex structures, use `get` + `let`:**

```sheaf
;; Manual extraction (more explicit)
(let [l1 (get params :layer1)
      l2 (get params :layer2)]
  (with-params [l1]
    (let [h1 (+ (@ x W) b)]
      (with-params [l2]
        (+ (@ h1 W) b)))))
```

### Validation Patterns: State & Gradient Debugging

Temporal models and complex computations can have subtle bugs because state flows through multiple steps—errors in one timestep propagate forward. Use these atomic validation patterns:

**Pattern 1: Validate state shape at each step**

```sheaf
;; Inside your RNN cell function:
(fn [h_prev x_t]
  (let [_ (guard :shape [8] h_prev)        ; h_prev must be [8]
        _ (guard :shape [1] x_t)           ; x_t must be [1]
        h_next (tanh (+ (@ W_hh h_prev)
                        (@ W_xh x_t)
                        b_h))
        _ (guard :shape [8] h_next)]       ; h_next must be [8]
    [h_next h_next]))
```

**Pattern 2: Detect vanishing/exploding gradients**

Vanishing gradients in RNNs happen when states shrink (< 0.01) or explode (> 10). Check state norms:

```sheaf
;; After scan completes, inspect hidden states
(let [[h_final all_h] (scan rnn-step h0 inputs)
      h_norms (tree-map (fn [x] (mean (abs x))) all_h)]
  (do
    (guard :range [0.01 10.0] h_norms)     ; States should have reasonable magnitude
    all_h))
```

**Pattern 3: Verify gradients flow backward through time**

If gradients are zero, the computation graph is broken:

```sheaf
;; Test: tiny parameter change should cause small loss change
(let [loss1 (loss-fn params)
      params-eps (tree-map (fn [x] (+ x 1e-4)) params)
      loss2 (loss-fn params-eps)
      diff (abs (- loss2 loss1))]
  (guard :range [1e-8 1.0] diff))  ; diff should be non-zero
```

**Pattern 4: Check for NaN/Inf propagation during scan**

Insert guards inside scan to catch where problems start:

```sheaf
(fn [h_prev x_t]
  (let [h_candidate (tanh (+ (@ W_hh h_prev) (@ W_xh x_t) b_h))
        _ (guard :no-nan h_candidate)      ; Catch NaN immediately
        h_next (maximum -1e6 (minimum 1e6 h_candidate))]  ; Hard clip
    [h_next h_next]))
```

**Pattern 5: Initialization sensitivity check**

RNNs are very sensitive to initialization. Test with different scales:

```sheaf
;; Try 3 initialization scales and compare convergence
(let [params-small (tree-map (fn [x] (* x 0.01)) params)
      params-medium (tree-map (fn [x] (* x 0.1)) params)
      params-large (tree-map (fn [x] (* x 1.0)) params)

      loss-small (loss-fn params-small)
      loss-medium (loss-fn params-medium)
      loss-large (loss-fn params-large)]
  (do
    (print "Small scale loss:" loss-small)
    (print "Medium scale loss:" loss-medium)
    (print "Large scale loss:" loss-large)))
```

**Best practice:** Use `init-xavier-uniform` or `init-lecun-normal` for RNN weights (scale ~0.1), not random initialization.

  ```sheaf

  (ones '[1])          ; Single dimension - must quote to get tuple, not array
  ```

- **Unquoted shapes** `[...]` for dynamic shapes with variables:
  ```sheaf
  (let [D 128 H 8]
    (ones [D H]))      ; Variables evaluated → shape (128, 8)
  ```

**Why quote?** Without quote, `[1]` becomes a JAX array. With quote, `'[1]` becomes a Python tuple `(1,)` - which is what shape functions expect.

### PyTree Operations

Pytrees are nested structures (dicts, lists) that JAX and Sheaf use for parameter storage. JAX treats these structures as first-class citizens, enabling automatic batching, vectorization, and gradient computation across nested hierarchies.

**Functions:**

| Function                | Description                   | Example                   |
| ----------------------- | ----------------------------- | ------------------------- |
| `(tree-map fn tree)`    | Apply function to all leaves  | `(tree-map relu params)`  |
| `(tree-map-zeros tree)` | Replace all leaves with zeros | `(tree-map-zeros params)` |

**Example 1 - Transform nested parameters:**

```sheaf
;; Square all elements in a nested structure
(let [params {:layer1 {:w [2.0 4.0] :b 0.5}
              :layer2 {:w [10.0]}}]
  (tree-map (fn [x] (* x x)) params))
; => {:layer1 {:w [4.0 16.0], :b 0.25}, :layer2 {:w [100.0]}}

;; Scale all gradients by learning rate
(tree-map (fn [g] (* g -0.001)) gradients)
```

**Example 2 - Initialize Adam Optimizer State (Correct):**

Adam optimizer requires two state variables (`m` and `v`) with the same nested structure as your parameters. This is a common source of bugs:

```sheaf
;; Parameters from your model
(let [params {:l1 {:w (random-normal key1 '[64 128])
                   :b (zeros '[128])}
              :l2 {:w (random-normal key2 '[128 10])
                   :b (zeros '[10])}}

      ;; CORRECT: Create optimizer state with matching structure
      m (tree-map-zeros params)        ; All zeros, same shape as params
      v (tree-map-zeros params)        ; All zeros, same shape as params
      t 1                              ; Step counter (starts at 1 for Adam)
      lr 0.001                         ; Learning rate]

  ;; Now use in training
  (let [loss-fn (fn [p] (cross-entropy-loss (forward x p) y))
        [loss grads] ((value-and-grad loss-fn) params)
        [new-p new-m new-v] (adam-step params grads m v t lr 0.9 0.999 1e-8)]
    {:params new-p :m new-m :v new-v :t (+ t 1) :loss loss}))
```

**Key Points:**

- ✅ `m` and `v` **must** have the same nested structure as `params`
- ✅ Use `tree-map-zeros` to ensure structure matching automatically
- ✅ ❌ **Don't** manually create `{:l1 {:w 0.0 :b 0.0}}` - this uses scalar 0.0 instead of matching the shape
- ✅ `tree-map` automatically recurses through all nested levels
- ✅ **adam-step returns 3 values** `[new-params, new-m, new-v]` - increment `t` manually for the next iteration

**Example 3 - Gradient Clipping with PyTree Inspection:**

```sheaf
;; Inspect gradient structure before applying clipping
(let [params {:net {:layer1 {:w W1 :b b1}
                    :layer2 {:w W2 :b b2}}}
      grads (grad-fn params)

      ;; Compute L2 norm of all gradients
      grad-norms (tree-map (fn [g] (sqrt (sum (** g 2)))) grads)

      ;; Clip all gradients by global norm
      clipped-grads (clip-by-global-norm grads 1.0)]

  ;; Apply clipped gradients
  (tree-map (fn [g] (* g -0.001)) clipped-grads))
```

**Example 4 - Multi-Task Learning with PyTree Operations:**

```sheaf
;; Shared parameters with task-specific heads
(let [shared-params {:backbone {:conv1 {:w W1 :b b1}
                                :conv2 {:w W2 :b b2}}}

      task-params {:task1 {:head {:w W_t1 :b b_t1}}
                   :task2 {:head {:w W_t2 :b b_t2}}}

      ;; Create optimizer state for both
      m-shared (tree-map-zeros shared-params)
      v-shared (tree-map-zeros shared-params)
      m-task (tree-map-zeros task-params)
      v-task (tree-map-zeros task-params)]

  ;; In training loop:
  (let [[task1-loss g1] ((value-and-grad loss1-fn) shared-params)
        [task2-loss g2] ((value-and-grad loss2-fn) shared-params)]

    ;; Update both backbones with averaged gradients
    (let [avg-grads (tree-map (fn [x y] (/ (+ x y) 2.0)) g1 g2)]
      (adam-step shared-params avg-grads m-shared v-shared t lr 0.9 0.999 1e-8))))
```

**Important:** `tree-map` can take multiple trees and will apply the function to corresponding leaves:

```sheaf
(tree-map (fn [x y] (+ x y)) tree1 tree2)  ; Adds corresponding leaves
```

### Random Numbers (JAX PRNG)

JAX uses explicit PRNG keys (not global state). Always create a key first, then split for independent samples.

| Function                                        | Description                                   |
| ----------------------------------------------- | --------------------------------------------- |
| `(random-key seed)`                             | Create PRNG key from integer seed             |
| `(random-split key)`                            | Split key → 2 independent keys                |
| `(random-split key n)`                          | Split into n independent keys                 |
| `(random-normal key shape)`                     | Sample from N(0,1)                            |
| `(random-uniform key shape)`                    | Sample from U(0,1)                            |
| `(random-randint key shape low high)`           | Sample random integers in range [low, high)   |
| `(choice key a shape [:p probs :replace bool])` | Sample from array with optional probabilities |

**Quick examples:**

```sheaf
;; Create independent keys for multiple random operations
(let [[k1 k2 k3] (random-split (random-key 42) 3)]
  {:normal (random-normal k1 '[10 10])
   :uniform (random-uniform k2 '[5 5])
   :integers (random-randint k3 '[20] 0 100)})

;; Sample from categorical distribution
(choice (random-key 0) 3 '[10] :p [0.1 0.3 0.6])
; => [0 0 2 2 2 2 2 1 1 2]  (sampled according to probabilities)

;; Sample with replacement from a range
(choice (random-key 0) 100 '[5])
; => [89 0 12 73 71]  (5 random integers from 0-99)
```

### Tracing

Configure via `Sheaf` instance:

```python
shf = Sheaf(trace='normal', scope='forward', log='console')
```

**Trace Levels:**

- `fast`: Function names, shapes, memory, time
- `normal`: + min/max ranges, NaN detection
- `verbose`: + mean values

### Guards (Runtime Assertions)

```sheaf
(guard :no-nan x)                  ; Fail if NaN/Inf
(guard :range [-10.0 10.0] x)      ; Fail if outside range
(guard :shape [64 256] x)          ; Fail if shape mismatch
```

Guards automatically convert Python scalars to JAX arrays, so you can use them with both scalars and tensors:

```sheaf
(guard :range [0.0 100.0] 42)      ; Works with scalar
(guard :range [0.0 100.0] tensor)  ; Works with array
```

Guards trigger an **Emergency Backtrace** (last 100 ops with shapes/stats) when violated.

## Best Practices

### 1. Use `sigmoid` for independent probabilities

```sheaf
(sigmoid attention-scores)  ; Each object can be selected independently
```

### 2. Use `softmax` for exclusive selection

```sheaf
(softmax logits :axis -1)  ; Only one class selected
```

### 3. Use `...` (ellipsis) for rank-agnostic code

```sheaf
(einsum "... i j, ... j k -> ... i k" A B)  ; Works for any batch dims
(get tensor ... -1)  ; Index last element regardless of rank
```

### 4. Use `if` for control-flow, `where` for data-flow

```sheaf
; Control-flow (non-differentiable):
(if (= epoch 0) init-lr (* lr 0.1))

; Data-flow (differentiable, JIT-safe):
(where (> x 0) x (* x 0.01))  ; Leaky ReLU
```

### 5. Leverage `with-params` for cleaner code

```sheaf
; Instead of:
(let [W (get params :W)
      b (get params :b)]
  (+ (@ x W) b))

; Write (legacy syntax):
(with-params params
  (+ (@ x W) b))

; Or with brackets (recommended):
(with-params [params]
  (+ (@ x W) b))

; Or with key shorthand (most elegant):
(with-params [params :l1]
  (+ (@ x W) b))

; With complex expression (compute params on the fly):
(with-params [(get layer-params layer-id)]
  (+ (@ x W) b))

; Or with transformation:
(with-params [(tree-map (fn [x] (* x scale)) (get params :l1))]
  (+ (@ x W) b))
```

## Common Tasks

### Load and compile Sheaf code

```python
from sheaf import Sheaf

shf = Sheaf()
shf.load_file("model.shf")
shf.compile("forward")  # Optional: explicit compilation
```

### Apply JAX transforms

```python
import jax

# Direct access to compiled functions
batched_forward = jax.vmap(shf.forward)
fast_forward = jax.jit(shf.forward)
```

### Training loop

```python
state = {"p": params, "m": m, "v": v, "t": 1}
for epoch in range(epochs):
    state = shf.train_step(state["p"], state["m"], state["v"],
                           state["t"], X, y, lr)
    print(f"Loss: {state['loss']}")
```

### Checkpointing with pytrees

```python
# Convert Sheaf state to pytree
tree = shf.to_pytree(state)

# Save (using Python, not Sheaf)
import safetensors
safetensors.save_file(tree, "checkpoint.safetensors")

# Load and restore
loaded_tree = safetensors.load_file("checkpoint.safetensors")
restored_state = shf.from_pytree(loaded_tree)

# Continue training
state = shf.train_step(restored_state, data)
```

**Properties:**

- `to_pytree` converts Sheaf values (dict, list, tensor, scalar) to JAX pytrees
- `from_pytree` reconstructs Sheaf values from pytrees
- Invertible: `from_pytree(to_pytree(x)) == x`
- Compatible with `jax.tree_util` operations
- Rejects non-serializable types (functions, symbols)
